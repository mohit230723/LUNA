# Plan 4.2: End-to-End Orchestrator Pipeline & Headless CLI Runner

## Objective
Implement `luna/orchestrator/pipeline.py` providing a clean, callable orchestrator pipeline class `LunaPipeline` that coordinates the entire multi-agent fraud investigation lifecycle from initial seeding to decomposition, isolation, execution, contradiction detection, conflict resolution, action approval, and cross-run learning. Create `scripts/demo.py` as an executable headless demo that runs the complete pipeline, records a replay trace, and prints a rich terminal summary.

## Context
- `.gsd/SPEC.md` (Goal 1-5, Headless CLI runner)
- `.gsd/REQUIREMENTS.md` (REQ-01 through REQ-17, NFR-01)
- Phase 1, Phase 2, Phase 3 modular components:
  - `seed_atlas`, `seed_domain`
  - `decompose_task`, `assign_skills_to_subtasks`
  - `extract_subgraph_slice`, `create_agent_mcp_server`, `AgentMCPClient`, `SubAgent`
  - `promote_findings`
  - `detect_contradictions`, `resolve_conflicts`
  - `propose_actions`, `approve_action`, `execute_action`, `evaluate_outcomes`
  - `learn_from_run`
  - `explain_customer`

<task type="auto">
  <name>Implement LunaPipeline Orchestrator Engine</name>
  <files>luna/orchestrator/pipeline.py, luna/orchestrator/__init__.py</files>
  <action>
    - Create `luna/orchestrator/pipeline.py` with:
      - `PipelineConfig` model:
        ```python
        class PipelineConfig(BaseModel):
            run_id: str = Field(default_factory=lambda: f"run_{uuid.uuid4().hex[:8]}")
            domain_graph: str = "domain"
            atlas_graph: str = "atlas"
            auto_approve: bool = True
            k_hops: int = 2
            llm_client: Optional[Any] = None
        ```
      - `PipelineStep` enum or string constants.
      - `PipelineEvent` model for streaming events to subscribers:
        - `step`: str
        - `message`: str
        - `data`: Optional[dict[str, Any]]
        - `timestamp`: str
      - `LunaPipeline`:
        - `__init__(store, config)`: registers optional event listener callback.
        - `run(task_description: str) -> PipelineRunResult`:
          - Step 1: Ensure/Seed graphs.
          - Step 2: Decompose task into subtasks.
          - Step 3: Match and assign skills from `atlas`.
          - Step 4: Extract k-hop slices for targets.
          - Step 5: Launch subagents in parallel or sequentially using scoped MCP servers.
          - Step 6: Promote findings into run memory with evidence validation.
          - Step 7: Detect contradictions (`[:CONFLICTS_WITH]`).
          - Step 8: Resolve conflicts (`[:UPHELD]`, `[:SUPERSEDES]`).
          - Step 9: Propose actions.
          - Step 10: Human approval gate (`approve_action` if `auto_approve=True`).
          - Step 11: Execute approved actions and record outcomes.
          - Step 12: Evaluate metrics against ground truth.
          - Step 13: Learn from run (update atlas reputation).
          - Step 14: Generate "Why?" path explanation for flagged entities.
          - Step 15: Return `PipelineRunResult` with full audit trace.
      - Export in `luna/orchestrator/__init__.py`.
  </action>
  <verify>pytest tests/test_pipeline.py</verify>
  <done>Clean, reusable orchestrator pipeline coordinates all stages seamlessly.</done>
</task>

# Plan 4.1: "Why?" Path Query Engine

## Objective
Implement the "Why?" path query module (`luna/orchestrator/explain.py`) that executes single Cypher path queries across `run_<id>` and `atlas` graphs to retrieve the complete audit trail and reasoning chain behind any action or decision (Action -> Decision -> Findings -> Evidence Entities -> Subtasks -> Skills).

## Context
- `.gsd/SPEC.md` (Goal 5: Post-Hoc Auditability & Explainability)
- `.gsd/REQUIREMENTS.md` (REQ-17: Why? Path Query Engine)
- `docs/schema.md` (Schema naming contract for run memory edges and nodes)
- Phase 3 results: `Decision`, `Action`, `Outcome`, `Finding` nodes, `[:BASED_ON]`, `[:UPHELD]`, `[:SUPERSEDES]`, `[:ASSESSES]`, `[:SUPPORTED_BY]`.

        ```python
        class ExplainResult(BaseModel):
            target_cid: str
            action: Optional[Action]
            decision: Optional[Decision]
            winning_finding: Optional[Finding]
            superseded_findings: list[Finding]
            evidence_entities: list[dict[str, Any]]
            equipped_skill: Optional[str]
            narrative: str
            graph_path: dict[str, Any]  # nodes & edges suitable for Cytoscape visualization
        ```
      - `explain_action(store: GraphStore, run_graph_name: str, action_id: str, atlas_graph_name: str = "atlas") -> ExplainResult`:
        - Traces the `(Action)-[:BASED_ON]->(Decision)-[:UPHELD]->(Finding)` path.
        - Fetches `(Decision)-[:SUPERSEDES]->(Finding)` superseded findings to explain why alternatives were rejected.
        - Fetches `(Finding)-[:SUPPORTED_BY]->(Entity)` for verified evidence.
        - Synthesizes human-readable narrative explaining why the action was taken.
        - Returns structured `ExplainResult`.
      - `explain_customer(store: GraphStore, run_graph_name: str, target_cid: str, atlas_graph_name: str = "atlas") -> ExplainResult`:
        - Convenience query resolving explanation by customer CID.
      - Export in `luna/orchestrator/__init__.py`.

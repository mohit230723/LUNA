# Plan 1.5: LLM Client, Task Decomposer & Skill Selection Engine

<objective>
Implement the `LLMClient` protocol (with `OllamaLLM` and deterministic `MockLLMClient`), task decomposition into capability-based subtasks, and graph-driven skill matching against the `atlas` catalog that logs chosen and rejected skills with explicit rationale.

Purpose: Bridges human task input to graph-native agent configuration, demonstrating dynamic skill equipping based on graph queries.
Output: `luna/llm/client.py`, `luna/planner/decompose.py`, `luna/atlas/assign.py`, and test suites in `tests/test_llm.py` and `tests/test_planner.py`.
</objective>

<task type="auto">
  <name>Task Decomposition and Atlas Graph Skill Matcher</name>
  <files>luna/planner/decompose.py, luna/atlas/assign.py, tests/test_planner.py</files>
  <action>
    1. In `luna/planner/decompose.py`, implement `decompose_task(task_text: str, task_type: str, llm: LLMClient) -> list[Subtask]`:
       - Prompts LLM to break the task into discrete subtasks, each requiring a specific capability (`link_entities`, `detect_communities`, etc.).
       - Returns list of `Subtask(id=..., description=..., capability=...)`.
    2. In `luna/atlas/assign.py`, implement `assign_skills_to_subtasks(store: GraphStore, subtasks: list[Subtask], task_type: str) -> list[AssignmentResult]`:
       - For each subtask capability, query `atlas`:
         `MATCH (s:Skill)-[:PROVIDES]->(c:Capability {name: $cap}) OPTIONAL MATCH (s)-[r:SUCCEEDED_ON]->(t:TaskType {name: $task_type}) RETURN s, r.score`
       - Evaluate candidate skills:
         - If `s.restricted == true`: REJECT with reason "Policy restriction: skill is restricted". (e.g. `bulk-linker`)
         - Check prerequisites `(s)-[:REQUIRES]->(req)`: if prerequisite skill not assigned, either plan it or note it.
         - Rank remaining candidates by `SUCCEEDED_ON.score` (highest wins, e.g. `ring-detector` (0.80) beats `ring-detector-lite` (0.50)).
       - Return `AssignmentResult` holding `chosen_skill`, `rejected_skills: list[tuple[skill_id, reason]]`, and `subtask`.
    3. In `tests/test_planner.py`, test with mock `GraphStore` / atlas data:
       - Verify task decomposition produces subtasks with expected capabilities.
       - Verify `bulk-linker` is rejected due to policy restriction despite high score.
       - Verify `ring-detector` is chosen over `ring-detector-lite` due to higher track record score.
       - Verify all rejection reasons are captured for explainability.
  </action>
  <verify>pytest tests/test_planner.py -v</verify>
  <done>Planner tests pass confirming capability matching, policy rejections, track record ranking, and structured provenance.</done>
</task>

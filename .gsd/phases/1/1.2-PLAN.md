# Plan 1.2: Synthetic Domain Generator & GraphRAG Ontology

<objective>
Generate a synthetic connected insurance dataset with planted fraud ring and decoy family clusters, export ground truth markers for precision/recall evaluation, and define the GraphRAG domain ontology schema (`ontology.json`).

Purpose: Provides the realistic connected domain data that agents will investigate, along with ground truth to mathematically verify agent decisions.
Output: `luna/domain/generate.py`, `luna/domain/seed.py`, `luna/domain/ontology.json`, and tests in `tests/test_domain.py`.
</objective>

<task type="auto">
  <name>Synthetic Insurance Domain Generator with Planted Clusters</name>
  <files>luna/domain/generate.py, luna/domain/seed.py</files>
  <action>
    1. Implement `luna/domain/generate.py` with function `generate_insurance_dataset(seed: int = 42) -> tuple[dict, GroundTruth]`:
       - Create ~300 `Customer` entities, ~300 `Policy`, ~500 `InsuranceClaim`, ~10 `Provider`.
       - Stable `cid` attributes on every node (`cust_1`, `claim_101`, `prov_ring`, etc.).
       - Plant Fraud Ring: 8 customers sharing `ba_ring` (BankAccount) and `ph_ring_1`, `ph_ring_2` (Phones), with high claim amounts (>$25,000) treated by `prov_ring`.
       - Plant Decoy Family: 4 customers sharing `addr_decoy` (Address) with distinct bank accounts, distinct phones, and normal claims (<$5,000).
       - Rest of population: realistic background connections with low collision rates.
       - Return `GroundTruth(ring_cids=set(...), decoy_cids=set(...), provider_cid="prov_ring")`.
    2. Implement `luna/domain/seed.py` with `seed_domain(store: GraphStore, seed: int = 42) -> GroundTruth` that populates the `domain` named graph using batch parameterized Cypher writes.
    AVOID: Unseeded randomness (e.g. `random.random()` without seed) or real customer PII.
  </action>
  <verify>python -c "from luna.domain.generate import generate_insurance_dataset; data, gt = generate_insurance_dataset(42); print(f'Ring size: {len(gt.ring_cids)}, Decoy size: {len(gt.decoy_cids)}')"; exit $LASTEXITCODE</verify>
  <done>Dataset generation produces exactly 8 ring customer CIDs and 4 decoy customer CIDs deterministically.</done>
</task>

<task type="auto">
  <name>Domain Ontology JSON and Domain Unit Tests</name>
  <files>luna/domain/ontology.json, tests/test_domain.py</files>
  <action>
    1. Create `luna/domain/ontology.json` defining the schema for FalkorDB GraphRAG SDK:
       - Node types: `Customer`, `Policy`, `InsuranceClaim`, `Provider`, `Phone`, `Address`, `BankAccount` with their properties (`cid`, `name`, `amount`, `date`, `address`, `phone_number`, etc.).
       - Relationship types: `HOLDS`, `FILED`, `TREATED_BY`, `USES_PHONE`, `LIVES_AT`, `PAYS_FROM`.
    2. In `tests/test_domain.py`, write tests:
       - Verify determinism: two calls with `seed=42` yield identical graph structures and CIDs.
       - Verify fraud ring properties: all 8 ring customers link to `prov_ring` and share `ba_ring`.
       - Verify decoy family properties: all 4 decoy customers share `addr_decoy` but do not connect to `ba_ring` or `prov_ring`.
       - Verify `ontology.json` syntax and structure.
  </action>
  <verify>pytest tests/test_domain.py -v</verify>
  <done>All tests pass confirming dataset determinism, ring/decoy structural guarantees, and valid ontology definition.</done>
</task>

# Plan 1.1: Docker Compose, Schema Constants & GraphStore Wrapper

<objective>
Establish project dependencies, Docker Compose setup for FalkorDB on port 6379, centralized graph schema/naming constants, and the `GraphStore` wrapper with connection pooling, parameterized query execution, and lifecycle management.

Purpose: Foundation for all graph persistence, multi-graph isolation, and integration tests across LUNA OS.
Output: Working `GraphStore` library, `docker-compose.yml`, schema definitions, and unit/integration tests in `tests/test_store.py`.
</objective>

<task type="auto">
  <name>Project Setup and FalkorDB Docker Configuration</name>
  <files>docker-compose.yml, pyproject.toml, luna/config.py</files>
  <action>
    1. Create `docker-compose.yml` specifying `falkordb/falkordb:latest` service named `falkordb`, port mapping `6379:6379`, and healthcheck.
    2. Create `pyproject.toml` configuring the `luna` package with dependencies: `falkordb`, `graphrag_sdk`, `langchain_ollama`, `mcp`, `pydantic>=2.0`, `fastapi`, `uvicorn`, `networkx`, `pytest`, `pytest-asyncio`.
    3. Create `luna/config.py` using `pydantic_settings` (or `pydantic.BaseModel` + `os.environ`) to load `FALKORDB_HOST` (default: "localhost"), `FALKORDB_PORT` (default: 6379), `OLLAMA_BASE_URL` (default: "http://localhost:11434"), `OLLAMA_MODEL` (default: "llama3.1:8b"), and `DEFAULT_RANDOM_SEED` (default: 42).
    AVOID: Hardcoding connection credentials or URLs in application code.
  </action>
  <verify>python -c "from luna.config import settings; print(settings.FALKORDB_PORT, settings.OLLAMA_MODEL)"</verify>
  <done>Settings module imports cleanly and resolves default FalkorDB (6379) and Ollama configurations.</done>
</task>

<task type="auto">
  <name>Schema Constants and GraphStore Connection Wrapper</name>
  <files>luna/graph/schema.py, luna/graph/store.py, tests/test_store.py</files>
  <action>
    1. In `luna/graph/schema.py`, define string constants for graph names: `GRAPH_ATLAS = "atlas"`, `GRAPH_DOMAIN = "domain"`, `run_graph_name(run_id: str) -> str`, `agent_graph_name(run_id: str, agent_id: str) -> str`. Define node labels (`Customer`, `Provider`, `InsuranceClaim`, `Policy`, `Skill`, `Capability`, `Tool`, `Finding`, `EvidenceRef`, `Decision`, `Action`, `Outcome`) and relationship types.
    2. In `luna/graph/store.py`, implement `GraphStore` wrapping `falkordb.FalkorDB`:
       - `query(graph_name: str, query_str: str, params: dict | None = None) -> list[dict]`
       - `delete_graph(graph_name: str) -> bool`
       - `list_graphs() -> list[str]`
       - Parameter verification: raise ValueError if query contains unsafe string interpolations or unparameterized variable tokens.
    3. In `tests/test_store.py`, write unit tests with a mock FalkorDB client verifying parameter passing, graph naming convention enforcement, and error handling when queries fail. Include an integration test that connects to local FalkorDB if available.
    AVOID: Using f-string or string concatenation for query parameters. Always pass `$param` in query and dict in params.
  </action>
  <verify>pytest tests/test_store.py -v</verify>
  <done>Unit tests pass with 100% mocked offline reliability, verifying parameterized query safety and schema naming functions.</done>
</task>

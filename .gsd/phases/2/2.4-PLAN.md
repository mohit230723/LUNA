# Plan 2.4: Finding Promotion Engine & Evidence Verification

## Objective
Implement the finding promotion engine that validates evidence CIDs against the agent's private graph slice before merging findings into the shared `run_<id>` memory graph, blocking hallucinated evidence and recording provenance edges.

## Context
- `.gsd/SPEC.md` (REQ-12: Finding Promotion Engine)
- `.gsd/phases/2/RESEARCH.md`
- `luna/agents/models.py` (Finding model)
- `luna/graph/store.py` (GraphStore wrapper)
- `luna/graph/schema.py` (Run graph naming)

## Tasks

<task type="auto">
  <name>Implement Promotion Validation & Persistence</name>
  <files>luna/orchestrator/promote.py, luna/orchestrator/__init__.py</files>
  <action>
    - Create `luna/orchestrator/promote.py` with:
      - `class PromotionResult(BaseModel)` containing `promoted: list[Finding]`, `rejected: list[tuple[Finding, str]]` (finding + reason).
      - `def promote_findings(store: GraphStore, agent_graph_name: str, run_graph_name: str, findings: list[Finding]) -> PromotionResult`.
    - For each finding:
      1. Evidence Validation: For every `cid` in `finding.evidence_cids`, run parameterized query:
         `MATCH (n) WHERE n.cid = $cid RETURN count(n) AS cnt` against `agent_graph_name`.
         If `cnt == 0`, REJECT with reason `"Evidence CID '<cid>' not found in agent graph slice"`.
      2. If valid, promote to `run_graph_name`:
         - CREATE `(:Finding)` node with all properties.
         - MERGE `(:Agent {id: $agent_id})` and CREATE `(:Finding)-[:PROMOTED_FROM]->(:Agent)`.
         - MERGE `(:Customer {cid: $target_cid})` and CREATE `(:Finding)-[:ASSESSES]->(:Customer)`.
         - For each valid evidence CID, MERGE `(:Entity {cid: $evidence_cid})` and CREATE `(:Finding)-[:SUPPORTED_BY]->(:Entity)`.
    - Return `PromotionResult`.
  </action>
  <verify>pytest tests/test_promote.py -k test_promote_valid_findings</verify>
  <done>Promotes findings with verified evidence and writes provenance graph structure to `run_<id>`.</done>
</task>

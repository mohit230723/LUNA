# Phase 3 Plan 2 Summary: Main-Agent Conflict Resolution

## Overview
Implemented main-agent conflict resolution logic in `run_<id>` evaluating active conflicting findings, arbitrating based on weighted confidence, structural evidence presence, and skill reputation scores from `atlas`, creating `Decision` provenance nodes, linking `[:UPHELD]` and `[:SUPERSEDES]` edges, and marking superseded findings without deleting any data.

## Implementation Details
1. **Module `luna/orchestrator/resolve.py`**:
   - Model `Decision`: `id`, `target_cid`, `chosen_verdict`, `confidence`, `reasoning`, `winning_finding_id`, `superseded_finding_ids`, `resolved_at`.
   - Function `resolve_conflicts(store, run_graph_name, atlas_graph_name, llm_client)`:
     - Detects active conflicting findings on distinct customer targets.
     - Calculates weighted arbitration score per finding:
       `score = (confidence * 0.50) + (0.30 if evidence_cids else 0.0) + (atlas_score * 0.20)`
     - Creates `(:Decision)` node with complete provenance metadata.
     - Links `(decision)-[:UPHELD]->(winner)` and `(decision)-[:SUPERSEDES]->(loser)`.
     - Sets `loser.status = 'superseded'` (strictly append-only, zero deletions).
2. **Exported Interface**: Added `resolve_conflicts` and `Decision` to `luna/orchestrator/__init__.py`.
3. **Tests Added**:
   - `tests/test_resolve.py`: Unit arbitration test with mock store, plus integration test on live FalkorDB validating node preservation, status mutation, and link creation.
